# 产品从-1到0

什么是产品思维？
这是一份求是潮产品方向传承下来的讲义：[产品从-1到0（PDF）](assets/product-minus-one-to-zero.pdf)。讲义成稿于 2021 年前后，具体示例偏旧，产品运营思路历久弥新。

## 学习路径

### 第一阶段：产品与体验「前言」「UX」「UI」「Interaction Design 交互设计」

- 产品与产品经理：互联网产品是功能与服务的集成；“产品”偏向产品的创生，“运营”偏向产品的迭代。
- UX：好体验的三要素 Useful、Usable、Desirable；五个更具体的评价指标 Learnability、Efficiency、Memorability、Error Rate、Satisfaction。
- Error Control：错误与目的有关。交互过于相似、高频功能与易错功能过近、错误触发过于容易，是三类常见的错误来源。
- UI：设计感（简洁明快、潮与惊喜）、基础布局（TabBar、侧滑菜单 / 抽屉、瀑布流、卡片）、组件细节（z轴与阴影、颜色模型与配色原则、尺寸、动效、icon）。
- 交互设计：五个维度 Words、Visual representations、Physical objects or space、Time / Animation、Behavior；四条原则 Discoverability、Consistency、Learnability、Readability；以及 Fitts' Law 与最小点击区域。

**阶段产出：** 挑一个你每天在用的 App，用 UX 五个指标和交互四条原则写一页评价。并尝试按“影响 ÷ 成本”排序列出改进建议。

### 第二阶段：产品思维与平台常识「产品思维」「产品迭代」「具体的平台开发」「求是潮产品线」

- 需求导向：一个需求是否值得做，先看它是否是个例、是否要求紧迫、能否适当满足。
- 边界意识：知识产权与监管（如icon、代码、设计思路的使用许可，平台与商店规则）、信息安全与用户隐私。
- 数据驱动：用埋点记录用户行为，用数据而不是感觉指导迭代；埋点需要精心设计。
- 平台差异：App、网页、插件、微信小程序各自的成本与完成方式。
- 求是潮产品线：历史产品的兴衰成败（问答堂、Bubble、Share、Notice 等）留下的启示。

**阶段产出：** 写一份文档判断产品是否值得做，说明用户场景、现有替代方案、发生频率与影响，并给出推进或拒绝的理由。

### 第三阶段：工作流与交付物（「工作流」「技术背景知识」「扩展」）

- 调研：先确认需求和竞品，再决定是否调研潜在用户。
- PRD（Product Requirement Document）：“概念化”（产品定位、竞品分析，可用 $APPEALS 等多维框架）+ “图纸化”（业务逻辑、页面逻辑、数据通路）。
- 原型：先用低保真原型梳理流程，常用工具有 Figma、墨刀等。
- 研发、测试、推广、运营与迭代：测试要覆盖误触等异常路径；推广先讲用户能解决什么问题；运营要建立反馈与迭代的闭环。

**阶段产出：** 为一个真实的小需求写一份 PRD 草稿（至少写清背景、目标、范围、主流程和验收标准），并画出其中一条关键流程。

## 练习

- [ ] 用 UX 的五项指标为一个校园产品打分，每项写一句证据。
- [ ] 找两处让你不舒服的交互，分别说明问题、原因与改法，思考它与哪条交互原则相悖。
- [ ] 用“个例 / 紧迫 / 能否满足”三个问题判断一个你想到的需求的实现可行性。
- [ ] 找出一个产品里的埋点痕迹（如“猜你喜欢”“继续观看”），推测它记录了哪些行为、用来做什么。
- [ ] 为一个小项目写一页 PRD 草稿，喂给AI制作，评价其完成度，记录心得。
