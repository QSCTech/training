# 产品从-1到0

怎样判断一个东西算不算“产品”，怎样评价体验的好坏，界面与交互为什么要这样设计，以及一个需求从想法走到线上的完整流程。它是产品运营方向的入门材料，也是后续产品经理概论、需求分析等节点的前置阅读。

求是潮内部流传于上古时期的讲义：[产品从-1到0（PDF）](assets/product-minus-one-to-zero.pdf)。讲义成稿于 2021 年前后，具体示例偏旧，但产品运营思路历久弥新。

## 阅读提示

- 讲义里的界面截图大多来自 2019—2021 年的产品（如 2021 年的网易云音乐首页、Material Design 的阴影与颜色），阅读时关注它在解释哪条原则，不必记住具体界面。
- 讲义中提到“图像放在 `src/img/你的名字/`”，那是它原来所在仓库的约定。在本仓库中，附件统一放在对应方向的 `assets/` 目录下，用相对路径引用，如本篇的PDF。
- 建议分三个阶段读完，每个阶段读完先完成一次作业产出，再进入下一阶段。不需要一次看懂所有术语，先建立印象，在练习中遇到再回头查。

## 学习路径

### 第一阶段：产品与体验（「前言」「UX」「UI」「Interaction Design 交互设计」）

建立评价产品的眼光，建议阅读：

- 产品与产品经理：互联网产品是功能与服务的集成；“产品”偏向产品的创生，“运营”偏向产品的迭代。
- UX：好体验的三要素 Useful（有用）、Usable（易用）、Desirable（令人渴望）；五个更具体的评价指标 Learnability、Efficiency、Memorability、Error Rate、Satisfaction。
- Error Control：错误与目的有关；交互过于相似、高频功能与易错功能过近、错误触发过于容易，是三类常见的错误来源。
- UI：设计感（简洁明快、潮与惊喜）、基础布局（TabBar、侧滑菜单 / 抽屉、瀑布流、卡片）、组件细节（z 轴与阴影、颜色模型与配色原则、尺寸、动效、icon）。
- 交互设计：五个维度（Words、Visual representations、Physical objects or space、Time / Animation、Behavior）、四条原则（Discoverability、Consistency、Learnability、Readability），以及 Fitts' Law 与最小点击区域。

**阶段产出：**挑一个你每天在用的 App，用 UX 五个指标和交互四条原则写一页评价。每条结论都要给出证据——截图或可复现的操作步骤，最后按“影响 ÷ 成本”排序列出改进建议。

### 第二阶段：产品思维与平台常识（「产品思维」「产品迭代」「具体的平台开发」「求是潮产品线」）

从“会评价”走到“会判断”，建议阅读：

- 需求导向：一个需求值不值得做，先问它是不是个例、是否紧迫、我们能否满足。
- 边界意识：知识产权与监管（icon、代码、设计思路的使用许可，平台与商店规则）、信息安全与用户隐私。
- 数据驱动：用埋点记录用户行为，用数据而不是感觉指导迭代；埋点需要精心设计，只记录有价值的数据。
- 平台差异：App（Android 与 iOS 是两套开发与设计规范）、网页、插件、微信小程序各自的成本与触达方式。
- 求是潮产品线：历史产品的成与败（问答堂、Bubble、Share、Notice 等留下的启示），以及运营中、潮内与概念中的产品。

**阶段产出：**写一段“这个功能该不该做”的判断：说明用户场景、现有替代方案、发生频率与影响，并给出推进或拒绝的理由。

### 第三阶段：工作流与交付物（「工作流」「技术背景知识」「扩展」）

产品从判断走向生产，建议阅读：

- 调研：先确认需求和竞品，再决定要不要打扰用户。
- PRD（Product Requirement Document，产品需求文档）：分为“概念化”（产品定位、竞品分析，可用 $APPEALS 等多维框架）和“图纸化”（业务逻辑、页面逻辑、数据通路）两部分。
- 原型：先用低保真原型把流程说清楚，常用工具有 Figma、墨刀等。
- 研发、测试、推广、运营与迭代：测试要覆盖误触等异常路径；推广先讲用户能解决什么问题；运营要建立反馈与迭代的闭环。

**阶段产出：**为一个真实的小需求写一份 PRD 草稿（至少写清背景、目标、范围、主流程和验收标准），并画出其中一条关键流程。

## 练习

- [ ] 用 UX 的五项指标为一个校园产品打分，每项写一句证据。
- [ ] 找两处让你不舒服的交互，分别说明问题、原因与改法，并指出它违反了哪条交互原则。
- [ ] 用“个例 / 紧迫 / 能否满足”三个问题判断一个你想到的需求，写成 200 字以内的结论。
- [ ] 找出一个产品里的埋点痕迹（如“猜你喜欢”“继续观看”），推测它记录了哪些行为、用来做什么。
- [ ] 为一个项目小功能写一页 PRD 草稿，再请同学按验收标准复述一遍，检查是否存在歧义。
