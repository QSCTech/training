# 产品经理概论与 PRD

产品工作从发现问题开始，经过目标和方案定义、设计评审、开发测试、上线和复盘，持续验证是否为用户创造了价值。

## 产品经理概论

求是潮产品经理的工作可以概括为三个要素：需求、策划、运营。

围绕这些工作，需要具备几类基本能力：

1. 用户调研：设计问卷、开展访谈，知道过程中该记录什么、注意什么。
2. 表达与说服：具备基本的PPT演示与讲演能力。
3. 沟通与组织：与团队成员对齐信息，组织主持小组会议。
4. 文档写作：掌握 Markdown ，了解常见产品文档的组成部分。
5. 原型设计：掌握 Figma 等原型工具的基本操作。

产品运营工作流程：

1. 预备阶段：调研目标用户提取需求，脑暴补全并按优先级排序，进而竞品分析，最终产出 PRD。
2. UI ：先完成低保真原型，包含页面、页面功能、跳转逻辑与大致文案；再进一步细化。
3. 技术实现与测试：开发过程中定期跟进研发进度。
4. 产品上线与运营：以产品反馈群为主，回答用户问题、记录需求，等待后续迭代。

## PRD 是什么

一份可执行的需求文档（PRD）至少要说明：

1. 背景与问题：谁在什么场景遇到了什么问题。
2. 目标与指标：希望改变什么，如何判断成功。
3. 用户与范围：目标用户、使用边界和不做什么。
4. 用户流程：主流程、异常流程和状态变化。
5. 功能需求：页面、字段、交互、权限和校验。
6. 原型与验收标准：低保真原型、输入输出和可测试条件。
7. 风险与依赖：技术、数据、合规和上线风险。

需求描述要让设计、开发和测试对同一行为有相同理解。避免“体验更好”“尽快优化”这类无法验收的表达。

## PRD 模板

```md
## 需求背景
## 目标与指标
## 用户故事
## 页面与交互
## 数据与权限
## 异常情况
## 验收标准
## 版本计划
```
