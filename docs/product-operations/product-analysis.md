# 产品分析

产品分析的目的，是通过拆解现有产品学习需求、交互逻辑和商业价值，为新的产品决策提供输入。

## 选择对象

优先选择结构清晰、自己实际使用过、能在一周内完成分析的产品。不要只罗列功能，应围绕一个具体用户和场景展开。

## 分析框架

1. 用户：目标人群、核心场景和高频任务。
2. 问题：用户为什么需要它，替代方案是什么。
3. 体验：首次使用、核心流程、异常状态和反馈。
4. 信息架构：页面层级、导航和内容组织。
5. 数据与增长：激活、留存、转化和分享路径。
6. 竞争与取舍：它做得好的地方、成本和局限。
7. 建议：按影响和成本排序，写出可验证的改进。

## 分析输出

每个结论都应有截图、数据、访谈或可复现的操作作为依据。建议把“事实”“推断”和“建议”分开写，避免把个人偏好当成用户需求。

## 练习

- [ ] 选择一个校园产品，画出首次完成核心任务的流程图。
- [ ] 记录两个让你不舒服的交互，并说明问题、原因和改进方案。
- [ ] 推荐两个小众工具，分别写清楚它解决的具体问题。
