## 内训方式

求是潮产品研发中心的内训实行“学习-项目制”。实习成员需要先经历数周的基础学习，再双向选择实习项目并继续相关学习，最终单人或组队完成实习项目并通过验收（验收形式由项目性质决定）。

根据旧有内训材料，我们有两大方向（26秋冬起不再区分），推荐大家交叉学习。

| 方向 | 学习路线 | 最终实践 |
| --- | --- | --- |
| 产品运营 | [产品运营方向](product-operations/产品运营方向.md)：了解产品 → 调研与分析 → 方案设计 → 项目验证 → 推广与迭代 | 产品方案、原型、测试与反馈闭环 |
| 技术研发 | [技术研发方向](technical-development/技术研发方向.md)：开发基础 → 前端或后端 → 协作开发 → 项目交付 | 可运行的 Web 项目与技术复盘 |

以及，我们会定期进行线上/线下的进度同步。

## 使用方式

每篇学习文档都包含正文和练习两部分。我们为你留出了子目录 `/notes` 来完成练习并记录笔记（同时也是为了防止拉取最新仓库时产生冲突）。技术研发方向和产品运营方向的首页都标出了建议的学习顺序。

适合自己的学习方式能够让内训（或是你自身的课程学习）事半功倍。以下是一些我们为你推荐的学习方式，你可以选择其一或是其他任何你认为最适合你的方式。

### 本地使用 obsidian
> 什么是 Obsidian ？
>
> Obsidian 是一款基于 Markdown 的本地优先、非线性知识管理软件。它是一个高度可定制的“第二大脑”工具，旨在帮助你将零散的想法通过链接编织成一张知识网络。你可以方便地使用各种插件和功能来建构起你的知识库。

我们为你准备了一个`obsidian`仓库，你可以**在 Obsidian 中打开克隆仓库的 `docs/` 文件夹作为 vault**（注意，不是打开整个仓库根目录）。

通过本地 `obsidian`，你可以通过修改 `status` 来标记已学习部分。每篇文档的 YAML frontmatter 都带有 `status: unread` 。完成学习后，将当前文档改为 `status: done`，打开 Obsidian 的关系图谱即可看到颜色反馈（`status: done` 的节点显示荧光绿，而 `status: unread` 的节点显示暗灰色）。图谱分组位于 `docs/.obsidian/graph.json`，你可以自行在本地修改。（拉取更新时需要先还原 `status: unread` ）

### 远程发布到 GitHub Pages
> 什么是 GitHub Pages ？
>
> 简单来说，GitHub Pages 是 GitHub 提供的一项免费静态网站托管服务。你可以把 HTML、CSS、JavaScript、图片等静态文件放在 GitHub 仓库里，GitHub 会自动把它们发布成一个可访问的网站。

如果你希望像博客一样，可以通过链接来访问自己的笔记仓库页面，可以直接在原文档的基础上修改并按照[教程](technical-development/github-pages.md)挂载在自己的 GitHub Pages 上。我们推荐你先把两个方向所有的英文名文档移动至子目录 `/notes` 下，每学习完一个节点再将**已修改过的**文档迁移回源目录以记录自己的学习进度。

### 在线富文本编辑
> 什么是富文本编辑？
>
> 富文本不只能打字，还能给文字加格式、加结构以及插入图片/链接/表格等非纯文字内容。

或许你也听说过 `Notion` 或是 `飞书云文档` 这样的在线协作与知识管理平台，它们都支持富文本编辑。当然，它们的设计哲学和侧重点有所不同。Notion 更侧重于高度自定义的工作空间；而飞书云文档则更侧重于开箱即用的高效协作（事实上产研的日常协作都在使用飞书）。它们的视觉效果更丰富，不过可自动化的程度相对较低。

如果你使用该方式进行学习，那么无需克隆仓库或使用 git 就可以立即开始。
